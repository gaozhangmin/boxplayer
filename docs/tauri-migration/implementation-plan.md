# Tauri 迁移实施计划

日期：2026-11-06。范围基线：[feature-inventory.md](feature-inventory.md) 的 D1–D17 和第 4 节；进度见 [progress.md](progress.md)。

## 执行约定

M0 文档和 M1 本机基线已完成；用户在 2026-11-06 明确授权用 goal 完成 M2，验收后停在 M3 前。每个 goal 只覆盖一个里程碑，阶段内部连续实现、检查并修复；满足验收后停止。M2 本机最小流程已验收，证据见 progress.md 和 m2-validation.md；M3 已于 2026-11-06 由用户授权以独立 goal 推进，完成后停在 M4 前。阶段变更写入进度表，功能取舍仍以功能方案为准。

每个阶段必须区分：源码实现、自动检查、原生启动、真实账号流程、目标平台运行、安装包验证。未运行、跳过、模拟通过不能记为目标平台通过。一个功能标为“完成”须满足其全部子项，阶段中的早期子集不能代表整行功能已经完成。

本项目只迁移桌面 Electron 的 Windows/macOS/Linux 实现。Android 手机/平板/TV、Apple 原生 iOS/iPadOS/macOS/tvOS 不修改；XbyVideoHub 仅作为交互参考。这里的 macOS 指新的 Tauri 客户端。

## 工程位置与隔离

在现有 `boxplayer/` 仓库内新增 `tauri-app/`，独立 package.json、pnpm-lock.yaml、Vite 配置和 `src-tauri/`。这样方案、迁移代码和 Electron 过渡导出器在同一个仓库可审阅、可追踪；现有根 package.json、入口和锁文件在 M1 不改。不要在工作区外另建未追踪的兄弟工程。

```text
tauri-app/
  src/entries/{main,player,settings}/
  src/components/ui/          # shadcn-vue 源码
  src/features/              # 按阶段迁入的业务组件
  src/platform/              # typed invoke、事件、请求适配器
  src-tauri/src/             # 启动与命令注册
  src-tauri/crates/           # gateway、storage、player、transfer 按需拆分
  src-tauri/capabilities/     # 按窗口授予所需权限
```

前端依赖 Vue 3.5、Pinia、shadcn-vue/Reka UI、Tailwind；Query/Virtual 等按实际功能引入。M1 安装前核对 shadcn-vue 与 Tailwind 主版本兼容性并锁定，不能把当前脚手架和旧配置混用。soia、Frame、cc-switch 是只读参考，不修改它们，也不通过绝对路径导入它们的源码。引入代码时记录来源版本、许可证和本地改动。

迁移期使用独立开发 identifier、端口、数据目录和协议，避免注册或读写正式 Electron 的数据与 OAuth 协议。正式产品 identifier、安装替换和更新通道在 M9 验收。旧 Electron 工程保持可运行，不提前删除第 6.7 节代码；避免运行会自动改版本号并清理目录的根 `pnpm run build`。

## 模块接口基线

以下是实施契约草案，随首个真实用例细化后锁定类型与测试。公共 DTO 用 schemaVersion，错误统一为 code/message/retryable；日志去掉鉴权头和签名链接。

| 接口 | 责任与边界 |
|---|---|
| `http_request` + `http_cancel` | Rust 接收 requestId、providerId/accountId、method、URL、headers、body、超时；返回状态、头、字节/文本和 finalUrl。保留 axios 的非 2xx、超时、取消语义；流式请求另走带 requestId 的分块事件和终止事件 |
| `ResolvedMedia` | `{sourceId, accountId, fileId, url, headers, expiresAt?}` 是不可拆分的值；媒体、字幕、预览、下载复用相同账号上下文，不取“当前选中账号”替代 |
| `player_open` / `player_close` | 传播放 sessionId、ResolvedMedia、起始秒数、字幕及播放队列；事件带 sessionId 和 itemId，防止旧窗口事件覆盖新视频进度；以实际 Tauri 注册名验证前缀方案 |
| `resolve_download_url` | Rust 发 requestId/accountId/fileId，TS SDK 响应同 requestId；超时、取消、刷新次数上限和账号失效有明确错误。关闭主窗口隐藏到托盘时仍须能应答 |
| `settings_get/update` | Rust 是持久化唯一写入点；主/设置/播放窗口通过版本化事件同步。Pinia 只存各 WebView 的 UI 状态，不假设跨窗口共享同一个实例 |
| `local_list` / `scan_start/cancel` | Rust 负责文件 IO，列表 DTO 保留稳定文件标识；扫描事件区分批次、进度、完成、失败；能力按 source/provider 清单呈现 |
| `migration_inspect/import` | 导出 manifest 带格式版本、来源版本、表清单、计数、校验摘要；目标独立目录事务导入，幂等、备份、失败回滚；凭据通过受保护的本机流程迁入 Rust，不写进可提交的 JSON 样例 |
| `transfer_create/pause/resume/cancel` | Rust 持久化任务/分片、IO、hash 和限速；TS 做提供商协议编排。任务状态事件带序号，关闭浏览器弹窗后继续工作 |

请求头策略集中在 Rust，按提供商/账号/目标主机计算；重定向逐跳处理凭据，不能把 Authorization/Cookie 泄露给无关主机。缩略图、mpv 和传输复用策略，不各写一套。只读源码检查不等于这些契约已实现。

## M1 可直接执行的任务

1. 核对当前 Git 状态，记录实际提交；定位/安装 Rust 工具链并检查 macOS 开发依赖，明确网络或安装阻塞。仅使用 pnpm 管理前端依赖。

7. 添加必要的设置持久化/窗口事件等行为测试，完成静态检查和真实 macOS 启动验证。把执行命令、退出状态和观察结果写入 progress。

在 `tauri-app/` 已提供下列脚本（本机安装的 Rust 位于 `.local/`，直接执行 Cargo 前按 README 设置其环境；`pnpm tauri` 会自动识别）：

```sh
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo test --manifest-path src-tauri/Cargo.toml
```

首次生成锁文件用 `pnpm install`，随后用 frozen-lockfile 复现。`pnpm build` 不修改根项目版本，也不删除 Electron dist/release。实际运行验证必须记录启动、折叠、设置同步、重启恢复、重复启动及托盘行为；失败修复后重跑相关检查。M1 不要求网盘登录和真实 mpv 播放，它们是 M2/M3 的停止条件。
