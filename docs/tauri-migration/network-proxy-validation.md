# 网络代理设置与 Dropbox 请求失败（2026-11-09）

## 已定位原因

原生 Gateway 和 Cookie 会话显式 `no_proxy()`，OAuth 令牌交换与账号信息请求因此绕过系统代理。当前 Mac 配置了手动 HTTP/HTTPS 系统代理；对 Dropbox 无凭据令牌端点的直连在连接阶段超时，同一端点经系统代理收到 HTTP 404（GET 请求不交换令牌）。原生修正版通过同一系统代理的独立请求测试已成功。

没有重放浏览器回调、读取或输出账号令牌，也未以无凭据连通测试代替完整 Dropbox 登录验收。

## 设置

新增「设置 → 网络与代理」：

- 跟随系统：默认值，旧配置缺少代理字段时兼容默认。使用环境/操作系统手动代理，macOS 同时遵循系统 ExceptionsList；当前实现不执行 PAC 脚本。
- 直连：不使用 HTTP 代理。
- 自定义：支持 HTTP、HTTPS、SOCKS5、SOCKS5H 地址，不接受 URL 内嵌账号密码、查询参数、路径或片段。
- 本机、私有局域网 IP、单标签主机名和 `.local` 地址保持直连。
- 「测试 Dropbox 连接」只访问固定公开端点，无授权码或账号令牌；可测试未保存的草稿设置，不改变当前设置。

设置通过现有原生 settings.json 版本事务持久保存。保存后更新共享代理策略并换用新 HTTP 连接池；Cookie 会话保留同一个账号隔离 jar，只重建客户端。无需重启应用；已在途请求保持原行为。

Gateway、登录、文件 API、远程媒体读取和封面下载使用同一策略。本地播放范围桥、下载读取本机桥和测速读取本机桥继续直连。网络共享 SMB/NFS/FTP 不通过 HTTP 代理。

错误提示不再仅为 HTTP request failed，改为区分连接失败/超时并提示检查网络与代理设置，不披露请求 URL、请求体或凭据。
