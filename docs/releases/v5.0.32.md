# BoxPlayer v5.0.32

## 重点更新：内置 MPV 成为默认播放器

BoxPlayer 桌面版现在默认使用内置 MPV 播放器，同时继续保留“内置网页播放器”和“自定义播放软件”作为可选方案。内置 MPV 面向本地媒体、网盘直链和 Emby 播放提供统一的高兼容播放路径：

- 支持 **macOS arm64 / x64、Windows x64、Linux x64 / arm64**。macOS 使用共享纹理渲染，Windows 与 Linux 使用软件画面通道。
- 支持播放/暂停、停止、进度跳转、音量、倍速、章节、播放列表、上一集/下一集、片头片尾标记、画面旋转与比例裁剪。
- 支持识别和切换视频内置音轨、内置字幕，并可加载外部音轨和同目录/在线外挂字幕。
- 保留网盘与媒体服务器播放所需的 `Authorization`、Cookie、User-Agent、Referer、Origin 等请求头；带鉴权的字幕和媒体流会通过账号感知的本地代理安全转发。
- 支持原画与可用清晰度切换，并在切换时继承网盘级鉴权信息，避免临时地址可获取但 MPV 播放返回 401/403。
- 当当前平台的 MPV 原生资源缺失或架构不匹配时，会给出明确诊断，不会误加载其他架构的动态库。

## 发布质量门禁

- 新增 Windows x64、Linux x64 / arm64、macOS arm64 / x64 的内置 MPV 构建、打包与真实播放验证。
- Release 在打包前会验证本地多音轨/字幕样片的播放与所有主要控制按钮。
- Release 会在各桌面平台验证真实网盘与 Emby 的 MPV 播放链路；当前覆盖阿里云盘、123 云盘、百度网盘、PikPak、夸克网盘、139 云盘、光雅云盘、Dropbox、OneDrive、Google Drive 与 Emby。
- 115、Box、189 当前不纳入真实账号 Release 门禁，但其功能仍保留。
- 打包任务直接复用已经通过播放测试的 MPV 候选资源，避免“测试的是一套、发布的是另一套”。

## 网盘与账号修复

- 修复 Google Drive 账号切换按钮无响应的问题；切换期间显示加载状态，并对 OAuth/账号信息请求增加超时与明确错误提示。
- 修复夸克网盘 Cookie 域与合并规则，改善回收站和受鉴权下载请求的稳定性。
- 修复 115 与 Box 刷新 Token 后未同步过期时间和轮换 Refresh Token 的问题，避免使用旧令牌反复重试。
- 改进 115、189、139/光雅云盘的上传、分片提交、请求头和错误诊断。
- 修复 PikPak 登录刷新与部分真实账号回归场景。
- 移除设置页中已经不适用的 WebDAV 独立设置入口，并恢复账号设置区显示。

## 其他改进

- 修复网页播放器字幕设置出现重复层级的问题。
- 改进文档索引原生模块和设置持久化的端到端验证。
- 增加官方 mpv 源码构建脚本、资源清单与架构检查，便于后续升级 libmpv。

## English

### Highlight: Embedded MPV is now the default player

BoxPlayer desktop now defaults to the embedded MPV player while keeping the built-in web player and custom external players available as alternatives.

- Supports **macOS arm64/x64, Windows x64, and Linux x64/arm64**. macOS uses shared-texture rendering; Windows and Linux use the software-frame path.
- Includes playback, pause, stop, seek, volume, speed, chapters, playlist navigation, intro/outro markers, rotation, and crop/aspect controls.
- Detects and switches embedded audio/subtitle tracks and can load external audio plus local, cloud, and online subtitles.
- Preserves provider-required `Authorization`, Cookie, User-Agent, Referer, and Origin headers for cloud and Emby playback. Authenticated subtitle and media requests use an account-aware local proxy.
- Supports original and alternate quality sources without dropping provider-level authentication during quality switches.
- Reports missing or architecture-mismatched native MPV resources explicitly instead of attempting to load an incompatible bundle.

### Release quality gates

- Added embedded MPV build, package, and real-playback validation for Windows x64, Linux x64/arm64, and macOS arm64/x64.
- Release builds exercise a local multi-track/subtitle fixture and the complete MPV control surface before packaging.
- Cross-platform real-account playback gates cover Aliyun Drive, 123 Cloud, Baidu Netdisk, PikPak, Quark, China Mobile 139 Cloud, Guangya, Dropbox, OneDrive, Google Drive, and Emby.
- 115, Box, and Tianyi 189 are currently excluded from the real-account release gate, while their product integrations remain available.
- Packaging reuses the exact MPV runtime candidate that passed playback validation.

### Cloud and account fixes

- Fixed an unresponsive Google Drive account switch and added bounded OAuth/account-info requests with actionable failure messages.
- Corrected Quark cookie-domain and cookie-merge handling for authenticated downloads and recycle-bin access.
- Persisted rotated refresh tokens and expiry timestamps for 115 and Box.
- Improved multipart upload, request-header, commit, and error handling for 115, Tianyi 189, and 139/Guangya.
- Improved PikPak refresh/login regression coverage.
- Removed the obsolete standalone WebDAV settings entry and restored the account settings section.

### Other improvements

- Removed the duplicated subtitle menu layer in the web player.
- Expanded end-to-end coverage for document indexing and settings persistence.
- Added official mpv source-build scripts, runtime manifests, and architecture checks for future libmpv upgrades.
